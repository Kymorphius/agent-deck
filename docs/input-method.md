# macOS 导航与输入模式

<!-- matrix/hardened: opt-in native input-source ownership for the TUI. -->

`1.16.26+matrix.73` 增加本地 macOS 输入法适配：列表和快捷键操作临时使用英文键盘，进入文字输入后恢复之前使用的输入法。

```sh
agent-deck config set ui.auto_input_method true
```

已打开的列表按 `Ctrl+T` 重载程序，或退出后重新运行。关闭功能：

```sh
agent-deck config set ui.auto_input_method false
```

也需要重载列表。开关默认关闭，保存在 `[ui]` 下。

## 行为

- 列表导航、会话切换列表、移动分组、选择按钮和开关时，临时切到系统的 ASCII 键盘。`j/k` 等快捷键直接送给 agent-deck，不经过拼音组词。
- 搜索、重命名、消息输入、备注和表单的文字字段恢复先前的输入法。表单里的按钮和文字字段按实际焦点区分。
- 进入本地或远程 AI 会话前恢复输入法；回到列表后再次启用英文键盘。适配只识别 agent-deck 的焦点，不推断 AI 会话内部 Vim、shell 或其它程序的模式。
- 原来使用英文键盘时，进入输入框仍然使用英文。在文字输入框内选择鼠须管后，下次返回列表、再进入输入框会恢复鼠须管。
- 恢复前核对当前输入源；用户另选的输入源优先。退出时只恢复本程序实际替换过的输入源，后台标签页的退出不会覆盖前台标签页的选择。

这通过 macOS 原生输入源接口实现，无需模拟 Shift、安装键盘监听器或改动鼠须管词库。它恢复鼠须管输入源，保留鼠须管自身的中英文状态、方案和学习数据。

## 切不过去时自己重试（matrix.100）

切换按"期望状态 + 持续对齐"执行，而不是假设一次调用必然成功。切换当下如果归属的
终端应用还没被系统算作前台（窗口刚激活时焦点上报可能早于前台切换），或者原生选择
被拒绝，这次期望会标记为未完成：

- 列表（导航态）不能靠下一次按键来补救。中文输入法会把那一下按键吃掉去组词，这个
  按键永远不会到达 agent-deck，所以重试必须由程序自己驱动。未完成的切换按
  150ms 重试，最多 12 次（约 1.8 秒），覆盖窗口激活这段时间。
- 之后由固定的 2 秒刷新节拍继续核对。输入源也可能在没有任何事件的情况下被改掉
  （用户手动切、别的应用恢复自己的偏好、同一终端的另一个标签页接管），所以每个节拍
  都会重新核对当前模式，而不只在模式切换时核对。
- 已经处于期望模式时，普通输出和重绘帧不做任何原生调用；重试只在未完成时排队，并且
  同时只排一个。
- 失焦的标签页仍然不碰桌面输入源；它保留待还原的输入源，等自己重新获得焦点再还原。

## 所有权可交接（matrix.104）

"临时切到 ASCII"这件事原来只记在单个进程里，于是有三种情况会把你留在英文键盘上：
同时开着两个列表时，在另一个标签页进输入框——那个实例自己从没抢过输入源，没有东西
可还原；持有 ASCII 的标签页在失焦状态下退出或被杀（失焦时按设计不碰桌面输入源，
以免覆盖前台标签页），待还原的记录随进程消失；重载或重启后新进程也不知道上一个
进程抢过。

现在抢到 ASCII 时会把"抢了什么、原来是什么、归属的终端应用 pid、进程 pid、时间"写到
`<数据目录>/runtime/input-method-owner.json`（原子替换，0600）。任何一个实例在进入文字
输入、而自己没有东西可还原时，会接着完成别人留下的还原，条件是全部满足：

- 记录属于**同一个终端应用**（pid 一致）。应用重启或重新登录后 pid 必然变化，上一次
  登录的记录因此不会被重放；
- 当前输入源正好**还是记录里那个被抢走的 ASCII 源**。你自己选的英文键盘不会被改掉；
- 本实例当前有焦点且终端应用在前台；
- 记录未超过 12 小时。

用掉即删除。只有记录属于本进程时才会被本进程清掉，所以释放自己的所有权不会丢掉
别人待还原的记录。

## 文字输入主动切中文（matrix.105）

默认行为是"只还原 agent-deck 自己拿走的输入源"。这在"它从没拿走过"的情况下会把你留在
英文键盘上——刚登录时系统本来就是英文、或者所有权记录已经被别的实例用掉。打开下面这个
开关，文字输入拿到焦点时就**主动**切到你的输入法：

```sh
agent-deck config set ui.input_method_text_source auto
```

也可以直接给一个输入源 id（例如 `im.rime.inputmethod.Squirrel.Hans`），空字符串恢复默认
行为。需要重载列表。

`auto` 按确定的顺序解析目标，不在多个输入法之间瞎猜：

1. 你上次在文字输入里实际用的那个（离开文字态时记下来，存在
   `<数据目录>/runtime/input-method-preferred.json`，跨重启有效）；
2. 系统里**唯一**启用的非 ASCII 键盘输入法；
3. 都不满足（启用了多个且还没记下过）就什么都不做，并在追踪日志里写明。

应用时机是"文字输入拿到焦点"，不是持续施加：

- 进入搜索、重命名、消息输入、备注、表单文字字段，或进入会话输入时切中文；
- 纯操作态（列表导航、按钮、开关、会话切换列表、分组移动）一律切 ASCII，并且每 2 秒
  持续核对——那些键是 agent-deck 自己的快捷键；
- 在输入框里**你自己**切成英文打几句英文，不会被改回去：普通按键和刷新帧都不重新施加，
  只有重新获得键盘焦点（从别的应用或别的标签页切回来）才会再按策略切一次；
- 输入框里已经是某个输入法时不动它，只把它记下来；
- 退出 TUI 只还原拿走的东西，绝不会在退出时把桌面切成中文。

## 输入态与操作态的完整分类（matrix.109 审计）

判定在 `Home.inputMethodNavigation()`，按**当前获得焦点的那个控件**分，不按对话框整体分。

**文字输入态（切到输入法）**

- 列表搜索 `/`、全局搜索、分组搜索（Alt+S）、zoxide 路径选择器、提示输入框；
- 分组与会话重命名、备注编辑；
- 新建会话：Name、Path、Model、Branch、自定义命令（选了 custom 时）、多仓库编辑态，以及
  **工具选项面板里的文字字段**（Claude 的 resume id / extra args / start query，OMP 的 8 个
  字段）——这一条是 matrix.109 修的，之前整个面板被当成操作态；
- 编辑会话对话框的文字字段、Fork 对话框的 Name/Group/Branch、编辑路径对话框的编辑态；
- 设置面板的文字编辑态、首次配置向导的配置目录、看板面板的筛选编辑态；
- **worktree 收尾对话框的合并目标**（matrix.109 修，之前整个对话框被当成操作态）；
- 进入会话之后（insert 态或 attach）。

**操作态（切到 ASCII）**

- 列表导航、会话切换列表、分组移动、按钮与开关；
- 新建会话里的工具选择器、各复选框、选项面板里的开关和选择器、`[ Create session ]`、
  `[ Save as default ]`；分组创建时的父级目标选择器；
- 帮助页、确认框、hook 信任框、滚动回看、上下文分页、会话选择器、代码块、MCP／技能／
  插件／Gemini 模型对话框，以及 watcher／agents／adopt／web 服务／死信／工具可见性面板；
- MCP 与技能对话框的首字母跳转：这里**必须**是 ASCII，否则那一下按键会被输入法拿去组词；
- 永久删除确认：要求输入字面量 `DELETE`，ASCII 才打得出来；
- worktree 收尾的两个复选框。

反馈对话框有一个自由文本步骤，但本分支 `hardenedNoPrompts = true` 使它永不出现，因此没有
纳入分类。新增带文字输入的组件时，`internal/ui/matrix_input_method_test.go` 里的
`TestInputMethodPanelAndDialogTextFields` 与 `TestInputMethodFormFields` 是对应的守卫测试。

## 诊断日志

输入源切换依赖终端的焦点上报和应用激活顺序，事后没有痕迹。需要排查时显式打开：

```sh
AGENTDECK_IME_DEBUG=1 agent-deck
```

每次决策记一行到 `<数据目录>/logs/input-method.log`（`AGENTDECK_IME_DEBUG` 也可以
直接写文件路径）：触发它的消息类型、导航态、是否前台、当前与目标输入源、是否完成、
重试次数。默认关闭，打开也不改变切换行为本身。

`matrix.103` 起追踪在配置之前打开，所以功能**没有生效**的原因也会记下来：SSH 会话、
无 cgo 构建、祖先链里没有终端应用（例如 TUI 跑在 tmux 里，或终端会话服务已被 launchd
收养）、`ui.auto_input_method` 关闭。成功时记录归属的终端应用 pid。从桌面上看
"功能没开"和"切换坏了"是一样的，重启后尤其容易混淆，所以先看这一行。

## 支持范围与验证

需要启用 CGO 的 macOS 构建、可以确认父进程所属的原生终端应用，以及终端焦点报告。Teft/iTerm2 这一类原生终端可识别所属应用。启动/重载时按所属终端应用的前台状态初始化，随后按终端焦点报告跟踪；收到失焦报告后，后台刷新和退出不切换输入源。通过 SSH 启动的 TUI、无原生终端祖先进程的 TUI、无界面 Web 服务、Linux 以及禁用 CGO 的构建不会控制 Mac 桌面的输入源。

常规测试使用替身，不改变真实输入源：

```sh
scripts/run-isolated.py go test -race ./internal/inputmethod ./internal/ui -run '^TestInputMethod' -count=1
```

`TestInputMethodNativeAcceptance` 默认跳过。需要单独从本机前台终端显式运行；它短暂选择指定的、已经启用的输入法，检查输入法 → ASCII → 输入法，并恢复开始时的输入源：

```sh
AGENTDECK_IME_ACCEPTANCE=1 \
AGENTDECK_IME_ACCEPTANCE_SOURCE=im.rime.inputmethod.Squirrel.Hans \
scripts/run-isolated.py go test ./internal/inputmethod -run '^TestInputMethodNativeAcceptance$' -v
```

最终交互验收：鼠须管中文状态进入列表，检查 `j/k` 不弹拼音候选；按 `/` 搜索中文；Esc 返回列表，再打开重命名和消息输入；进入 AI 会话后正常输入中文；切换窗口和退出列表时检查输入法状态。

`matrix.74` 修复普通终端经过 root 所有的 `login` 进程时归属识别失败，以及 Teft 重载不发送首次焦点事件时一直等待的问题。升级前仍在运行的旧版可能在保存配置时丢弃新增字段，升级后应读回 `agent-deck config get ui.auto_input_method` 确认开启。
